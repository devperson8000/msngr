# Calling Implementation Plan

> Implement inline with superpowers:executing-plans. User requested no approvals or PRs.

**Goal:** Add voice/video calling, screen sharing, media controls, and in-call chat.
**Architecture:** WebRTC engine + call view + authenticated Supabase transport; app hooks on login, inbox refresh, conversation open, and signout.
**Tech Stack:** Native WebRTC, Vite, Supabase Realtime, Node tests and Playwright.
**Spec:** docs/superpowers/specs/2026-10-07-calling-design.md

## Global Constraints
- One-to-one direct conversations only; no public signaling fallback.
- Native permission prompts remain necessary. Do not embed TURN credentials in browser bundles.
- No PR, review approval, or deployment claim without actual access.

## Review Focus
- Cancellation during asynchronous media capture must release late tracks.
- Signaling is private and conversation-scoped; reject outsiders/stale calls.
- Simultaneous calls, repeated accepts, early ICE, and lost signaling cannot leak devices.
- Camera and screen can operate independently; toggles must reflect transmitted media.
- TURN cannot be assumed available; document hosted prerequisites.

## Results

Completed inline in the existing isolated checkout without PRs or approval gates. 19/19 tests passed with a local TCP TURN relay, including real audio, camera and screen RTP, UI controls/chat, permission denial, pending-capture cancellation, stale invitation rejection, busy/repeated accept, timeout cleanup, early ICE, restart, private-transport denial/recovery, and TURN credential/auth checks. Syntax checks, production build, existing auth UI smoke, desktop/mobile inspection, and git diff whitespace checks passed.

A separate read-only reviewer identified three stale media-operation races; each was reproduced with a failing test and fixed. The development ICE override was gated from production. The recovery regression revealed connected peers can remain marked reconnecting after ICE restart without a connection-state event; ICE-state/answer recovery now clears that state.

Hosted signaling RLS, real hardware/pickers and cross-network TURN remain unverified. No hosted migration, push, PR, or Vercel deployment was performed; required connector/admin access was not available. README documents the required migration, server-only TURN configuration, and validation boundaries.
