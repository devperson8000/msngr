# msngr calling

Build one-to-one voice and video calls between direct-conversation contacts. Include incoming accept/decline, busy handling, ringing timeout, hangup, microphone mute, camera toggle, independent screen sharing, elapsed time, connection feedback, and ephemeral in-call chat. Keep the existing messaging UI intact and fit the dark emerald visual style on desktop and mobile.

Use native WebRTC with audio processing and ideal 720p/30fps camera capture. Reserve audio, camera, and screen transceivers so controls need no renegotiation. A reliable ordered RTCDataChannel carries in-call chat and media-state notifications. Supabase private Broadcast channels scoped to a direct conversation carry invitations and SDP/ICE; an SQL migration restricts channel send/read to its two authenticated members. No public signaling fallback. TURN configuration is injectable through a Vercel server endpoint using short-lived REST credentials, with optional externally supplied ICE JSON for development. STUN alone cannot guarantee connectivity.

A separate engine owns state, tracks, peer connection, timers, signal validation, and cleanup. A view owns accessible call controls and rendering. An app controller owns private channel subscriptions and maps existing authenticated conversations into call contexts. Only the caller creates the offer after explicit acceptance. ICE is buffered until the remote description exists. All asynchronous capture/setup work checks session identity after awaits; cancellation releases late-acquired devices. Refuse mismatched call IDs and nonparticipants. Stop owned tracks and timers on every terminal path, signout, and unload. Retry ICE once on transient disconnect, then give an actionable failure.

Tests use two Chromium contexts with real RTCPeerConnections and deterministic media, connected by a test-only signaling harness. Verify media bytes, chat delivery, controls, early ICE, decline/busy, cancellation, denied capture, reconnect cleanup, and responsive UI. Test the Supabase adapter separately with deterministic transport responses. Hosted signaling RLS, real devices, screen picker, TURN across networks, and Vercel deployment require external access and must be reported separately.
